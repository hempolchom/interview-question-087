Functional Specification Document (FSD)

ข้อกำหนดฟังก์ชันการทำงานระบบพิสูจน์ตัวตน (Authentication System - Full Stack)

1. ภาพรวมระบบ (System Overview)

ระบบพิสูจน์ตัวตน (Authentication System) พัฒนาขึ้นแบบ Full-Stack เพื่อให้บริการสมัครสมาชิก (Register) และเข้าสู่ระบบ (Login) อย่างปลอดภัย โดยมี Frontend พัฒนาด้วย Angular (Standalone Components), Backend พัฒนาด้วย Go (Gin Framework / GORM) และจัดการข้อมูลด้วย PostgreSQL บน Docker Environment

2. ข้อกำหนดฟังก์ชันการทำงาน (Functional Requirements)

Module Feature Description / Rule Priority
Register (IT 02-2) User Registration
  • กรอกชื่อผู้ใช้ (User), รหัสผ่าน (Password) และ ยืนยันรหัสผ่าน (Confirm Password)
  • ตรวจสอบความถูกต้องของข้อมูลก่อนส่ง API (Client-side Validation)
  • บันทึกผู้ใช้ลงฐานข้อมูลพร้อมสุ่ม Salt เข้ารหัส bcrypt
 HIGH
Login (IT 02-1) User Authentication
  • กรอกชื่อผู้ใช้ (User) และ รหัสผ่าน (Password)
  • ตรวจสอบข้อมูลกับ PostgreSQL Database ผ่าน Go API
  • คืนค่า JWT Token เมื่อยืนยันตัวตนสำเร็จ และเก็บลง localStorage
 HIGH
UI / UX Validation Input Restriction & Highlight
  • User Field Restriction: อนุญาตเฉพาะภาษาอังกฤษ ตัวเลข และขีด (a-z, A-Z, 0-9, _, -) ผ่าน SqlCleanDirective
  • Required Field Marker: แสดงเครื่องหมายดอกจันสีแดง * ท้าย Label
  • Error Feedback: แสดงกรอบสีแดงและพื้นหลังสีแดงอ่อน (#ffebee) เมื่อไม่กรอกข้อมูล หรือกรอกรหัสผ่านไม่ตรงกัน
  • Toggle Password: ปุ่มไอคอนดวงตาสลับเปิด-ปิดดู Password และ Confirm Password
  • Notification: แสดง SweetAlert2 แจ้งสถานะ Success, Warning และ Error
 HIGH
Security & Middleware Data Security
  • กรองอักขระพิเศษสุ่มเสี่ยง SQL Injection / XSS ตั้งแต่ระดับ Client
  • ป้องกันการสมัครสมาชิกด้วยชื่อผู้ใช้ (Username) ซ้ำในระบบ
  • ปกป้อง Endpoint ด้วย JWT Middleware
 HIGH

3. ข้อกำหนดที่ไม่ใช่ฟังก์ชันการทำงาน (Non-Functional Requirements)

Category Specification
Security
  • รหัสผ่านต้องได้รับการ Hash ด้วยอัลกอริทึม bcrypt เท่านั้น ห้ามบันทึก Plaintext
  • การยืนยันสิทธิ์ API ใช้มาตรฐาน Bearer JWT Token
Performance
  • API Response Time ไม่เกิน 500ms สำหรับการสมัครสมาชิกและเข้าสู่ระบบ
  • Database Indexing บนฟิลด์ username เพื่อความเร็วในการ Query
Usability & Compatibility
  • รองรับการแสดงผลแบบ Responsive บน Web Browsers มาตรฐาน (Chrome, Firefox, Edge, Safari)
  • มี Visual Feedback ชัดเจนเมื่อกรอกข้อมูลผิดพลาด
Deployment Environment
  • รองรับการรันผ่าน Docker Compose เพื่อ Container Orchestration
  • รองรับการพัฒนาแบบรันแยกบริการ (Manual Local Setup)

4. การจัดการข้อผิดพลาดและข้อความแจ้งเตือน (Error Handling & Messages)

Scenario UI / System Behavior Alert Message (SweetAlert2)
กรอกข้อมูลไม่ครบถ้วน / ฟิลด์ว่าง ไฮไลท์กรอบแดง + พื้นหลังแดงอ่อนบน Input ที่ว่าง Warning: ข้อมูลไม่ถูกต้อง (กรุณากรอกข้อมูลให้ครบถ้วน)
Password และ Confirm ไม่ตรงกัน ไฮไลท์กรอบแดง + พื้นหลังแดงอ่อนบน Password & Confirm Input Error: รหัสผ่านไม่ตรงกัน (กรุณาตรวจสอบรหัสผ่านใหม่อีกครั้ง)
Username ซ้ำในระบบ (Register) Backend คืนค่า 400 Bad Request Error: สมัครสมาชิกไม่สำเร็จ (ชื่อผู้ใช้งานนี้มีอยู่ในระบบแล้ว)
Username/Password ผิด (Login) Backend คืนค่า 401 Unauthorized Error: เข้าสู่ระบบไม่สำเร็จ (ชื่อผู้ใช้งานหรือรหัสผ่านไม่ถูกต้อง)
เข้าสู่ระบบสำเร็จ Redirect ไปยังหน้า Welcome Success: เข้าสู่ระบบสำเร็จ (Timer 1.5s)
