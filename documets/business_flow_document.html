Business Flow Document (BFD)

เอกสารอธิบายกระบวนการทางธุรกิจและการไหลของงาน (Business Logic & Operational Workflow)

1. กระบวนการสมัครสมาชิก (User Registration Flow)

ขั้นตอนการทำงานทางธุรกิจเมื่อผู้ใช้งานใหม่ต้องการลงทะเบียนเข้าสู่ระบบ:

  1. การป้อนข้อมูล (Data Input): ผู้ใช้กรอก User, Password และ Confirm Password
  2. การกรองข้อมูลแบบเรียลไทม์ (Input Sanitization): SqlCleanDirective กรองตัวอักษรไม่อนุญาตออกทันที อนุญาตเฉพาะอักขระ a-z, A-Z, 0-9, _, -
  3. การตรวจสอบความถูกต้อง (Client-Side Validation):
    • หากไม่ได้กรอกข้อมูล ระบบจะแสดงกรอบและพื้นหลังสีแดงอ่อน (#ffebee) พร้อมเตือนด้วย SweetAlert2
    • หาก Password และ Confirm Password ไม่ตรงกัน ระบบจะเปลี่ยนพื้นหลังช่องรหัสผ่านเป็นสีแดงอ่อนและเตือน "รหัสผ่านไม่ตรงกัน"
  4. การประมวลผลฝั่งเซิร์ฟเวอร์ (Server Processing):
    • ส่ง HTTP POST ไปที่ Go Backend (/api/v1/auth/register)
    • ระบบตรวจสอบความซ้ำซ้อนของ Username ในฐานข้อมูล PostgreSQL
    • หากไม่ซ้ำ รหัสผ่านจะถูกเข้ารหัสด้วย Bcrypt และบันทึกลงตาราง users
  5. ผลลัพธ์ (Outcome): แสดง Pop-up แจ้งเตือนสำเร็จและ Redirect ผู้ใช้ไปยังหน้าเข้าสู่ระบบอัตโนมัติ

2. กระบวนการเข้าสู่ระบบและพิสูจน์ตัวตน (Authentication & Login Flow)

ขั้นตอนการยืนยันตัวตนสำหรับผู้ใช้งานที่มีบัญชีในระบบเรียบร้อยแล้ว:

  1. การป้อนข้อมูล (Credentials Input): ผู้ใช้กรอก User และ Password
  2. การส่งข้อมูลพิสูจน์ตัวตน (Authentication Request): ส่ง HTTP POST ไปที่ Go Backend (/api/v1/auth/login)
  3. การตรวจสอบสิทธิ์ (Verification):
    • Go Backend ทำการดึงข้อมูลจากตาราง users ตาม Username
    • เปรียบเทียบรหัสผ่านด้วย Bcrypt Compare
  4. การออกเหรียญยืนยันตัวตน (JWT Issuance):
    • หากถูกต้อง Backend สร้าง JWT Token และส่งกลับไปที่ Frontend
    • Frontend นำ Token ไปเก็บบันทึกไว้ใน localStorage สำหรับใช้แนบ Header Authorization ใน API ถัดไป
  5. ผลลัพธ์ (Outcome): แสดง Pop-up แจ้งเตือนเข้าสู่ระบบสำเร็จ แล้วนำผู้ใช้เข้าสู่หน้า Welcome/Dashboard

3. สรุปกฎทางธุรกิจ (Business Rules Matrix)

Rule ID Business Rule System Enforcement
BR-001 Username Format Constraint จำกัดตัวอักษรเฉพาะภาษาอังกฤษ ตัวเลข ขีดกลาง และขีดล่าง (^[a-zA-Z0-9_-]+$)
BR-002 Password Match Integrity รหัสผ่านยืนยันต้องตรงกัน 100% มิฉะนั้นจะไม่สามารถส่งคำขอไปยัง Backend ได้
BR-003 Username Uniqueness บัญชีผู้ใช้งานห้ามซ้ำกันในระบบ (Enforced by DB Unique Index & API Logic)
BR-004 Password Storage Security ห้ามจัดเก็บรหัสผ่านแบบ Plaintext ให้ใช้การ Hash ด้วย Bcrypt เท่านั้น
BR-005 Session Stateless Security การยืนยันตัวตนต้องใช้ JWT (JSON Web Token) แบบ Bearer Authentication
